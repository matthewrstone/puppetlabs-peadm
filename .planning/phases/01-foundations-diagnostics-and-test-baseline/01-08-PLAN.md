Shell setup for every command: `export PATH="$(ruby -e 'puts Gem.user_dir')/bin:$PATH"`. Commands assume cwd is the repo root.

Design decision (Claude's discretion for FND-06 per-path modes): copy_file gets an optional `mode`; when omitted, a path containing `/secrets/` gets `0600` and anything else `0644`. Owner and group stay root:root as today. Reasoning: peadm copies the key stores before PE provisions the replica so PE keeps the primary's keys; PE's own Puppet run on the replica then manages those files' ownership and mode (assumption; the primary-side modes are recorded by the node check in plan 01-09 and a DR run in Phase 4 F-scenarios confirms the replica services read them). `tasks/mkdir_p_file.sh` already applies chown/chmod to the empty file before it writes content, so there is no world-readable window and no task change is needed. Call sites in plans/subplans/configure.pp, plans/add_replica.pp and plans/add_compilers.pp need no change because the default covers them.

Plan-output capture technique (proven in research against peadm::install): wrap the BoltSpec executor's publish_event and collect every `:message` event; also capture `fail_plan` messages from the returned result.

```ruby
messages = []
allow(executor).to receive(:publish_event).and_wrap_original do |orig, event|
  messages << event[:message] if event[:type] == :message
  orig.call(event)
end
```

Signed-URL defect: plans/upgrade.pp:82 logs `$pe_installer_source.split('/')[-1]` and :144 uses the same expression for `$pe_tarball_name`; plans/subplans/install.pp:257 does the same and then derives `$pe_installer_dir` with `regsubst('\.tar(\.gz)?$', '')`, which does not strip the suffix when a query string follows it. The full URL must still be used as the download source; only the name derived from it changes.

| Primary's secret key stores -> replica and compiler filesystems | Encryption keys cross hosts through read_file / mkdir_p_file |

| Operator parameters (passwords, keys, signed URLs) -> Bolt plan output and CI logs | Anything printed by out::message lands in terminals and logs |
