Design decision (user decision A in revision round 3: tighten now): copy_file gets an optional `mode`; when omitted, a path containing `/secrets/` gets `0600` and anything else `0644`; owner and group stay root:root. Why 0600 rather than the source file's mode: (1) the source mode could itself be world-readable on an older primary, so copying it would not fix the defect; (2) taking the source mode needs a stat from `peadm::read_file`, which embeds the path in Python source (RESEARCH V5 note), so leaving that task untouched is safer; (3) 0600 is deterministic and testable. Only replicas receive secrets/ copies (plans/subplans/configure.pp and plans/add_replica.pp); compilers receive only hiera.yaml (plans/add_compilers.pp), which keeps 0644. peadm copies the key stores before PE provisions the replica so PE keeps the primary's keys, and PE's own Puppet run on the replica is expected to set the final owner and mode before its services read them. That expectation is the risk, so it becomes a gate: plan 01-13's acceptance adds one replica (widening D-12 by one node) and checks that the replica's pe-orchestration-services and pe-console-services users can read the three files and the services are active; if not, plan 01-14 reverts the secrets/ default to 0644 and records the follow-up. `tasks/mkdir_p_file.sh` already applies chown/chmod to the empty file before it writes content, so there is no world-readable window. Callers need no change because the default covers them.

Plan-output capture technique (proven in research against peadm::install): wrap the BoltSpec executor's publish_event and collect every `:message` event; also capture `fail_plan` messages from the returned result.

```ruby
messages = []
allow(executor).to receive(:publish_event).and_wrap_original do |orig, event|
  messages << event[:message] if event[:type] == :message
  orig.call(event)
end
```
