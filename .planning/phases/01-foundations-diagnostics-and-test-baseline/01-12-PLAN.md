Design decision (checker warning W6, lower-risk option): copy_file's targets are always replicas and compilers (plans/subplans/configure.pp, plans/add_replica.pp, plans/add_compilers.pp). Writing the orchestrator and console key stores there as root:root 0600 would only be safe if PE's Puppet run on those nodes resets ownership before the services read the files, and no Phase 1 acceptance run has a replica or compiler (D-12: standard architecture), so that cannot be verified here. Phase 1 therefore adds an optional `mode` parameter to copy_file with the default unchanged (0644, root:root), covers copy_file with its first spec, and does NOT change any caller. The tightening is recorded as a deferred follow-up for the Phase 4 DR acceptance run (F-scenarios / P-01), which can check that the replica and compiler services still read the copied keys; plan 01-13's node check records the primary-side owner and mode of those files as input for it. `tasks/mkdir_p_file.sh` already applies chown/chmod to the empty file before writing content, so a future stricter mode has no world-readable window.

Plan-output capture technique (proven in research against peadm::install): wrap the BoltSpec executor's publish_event and collect every `:message` event; also capture `fail_plan` messages from the returned result.

```ruby
messages = []
allow(executor).to receive(:publish_event).and_wrap_original do |orig, event|
  messages << event[:message] if event[:type] == :message
  orig.call(event)
end
```

Signed-URL defect: plans/upgrade.pp:82 logs `$pe_installer_source.split('/')[-1]` and :144 uses the same expression for `$pe_tarball_name`; plans/subplans/install.pp:257 does the same and then derives `$pe_installer_dir` with `regsubst('\.tar(\.gz)?$', '')`, which does not strip the suffix when a query string follows it. The full URL must still be used as the download source; only the name derived from it changes.
