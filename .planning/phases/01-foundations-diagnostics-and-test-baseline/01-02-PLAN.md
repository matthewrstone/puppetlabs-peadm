Harness API to implement (prototype from RESEARCH.md "Harness core", ran green against pe_install.sh; rewrite it RuboCop-clean, no endless defs, no rescue modifier):

```ruby
class ShellTaskHarness
  REPO = File.expand_path('../..', __dir__)
  attr_reader :root, :stubs
  def initialize            # mktmpdir; mkdir <root>/stubs and <root>/modules/peadm/{tasks,files}; copy REPO/files/*.sh into files/
  def stub(name, body)      # write executable <stubs>/<name>: "#!/bin/bash\necho \"$0 $*\" >> <root>/<name>.calls\n<body>"
  def calls(name)           # lines of <root>/<name>.calls, [] if absent
  def run(task, params = {}, env = {})  # copy REPO/tasks/<task> into modules/peadm/tasks, run /bin/bash with
                            # {'PATH' => "#{stubs}:#{ENV['PATH']}", 'LANG' => 'C'} + PT_<k> params + env;
                            # returns { stdout:, stderr:, status: exitstatus, json: parsed stdout or nil }
  def cleanup               # rm_rf root
end
```

Redaction filter (tested against planted secrets in research; GNU sed, Linux only):

```bash
peadm_redact() {
  sed -E \
    -e '/-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----/,/-----END [A-Z0-9 ]*PRIVATE KEY-----/c\
[REDACTED PRIVATE KEY]' \
    -e 's#(://[^/@[:space:]:]+):[^/@[:space:]]+@#\1:[REDACTED]@#g' \
    -e 's/([?&;](X-Amz-Signature|X-Amz-Credential|X-Amz-Security-Token|Signature|sig|token|access_token|api[_-]?key|key)=)[^&[:space:]"'"'"']+/\1[REDACTED]/Ig' \
    -e 's/((Authorization|X-Authentication|Proxy-Authorization)[[:space:]]*:[[:space:]]*(Bearer |Basic |Token )?)[^[:space:]"]+/\1[REDACTED]/Ig' \
    -e 's/("?[A-Za-z0-9_:.-]*(password|passwd|passphrase|secret|token|api[_-]?key|private[_-]?key|credential)[A-Za-z0-9_:.-]*"?[[:space:]]*[=:][[:space:]]*)("[^"]*"|'"'"'[^'"'"']*'"'"'|[^[:space:],}]+)/\1[REDACTED]/Ig'
}
```

| Target node logs / systemctl output -> Bolt task result | Installer and service logs can contain secrets; Bolt prints the task `_output` unredacted to the operator and to CI logs |
| Code-manager API response -> task output | Response bodies may echo tokens or paths |
| PT_* task parameters -> shell | Operator- and plan-supplied values reach bash |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | package installs | low | accept | No package-manager installs in this plan; uses only gems installed in 01-01 |
| T-01-04 | Information disclosure | files/failure_report.sh log tail | high | mitigate | `peadm_redact` runs over the whole log before `tail`; planted-secret specs for every rule (Task 1, Task 2) |
| T-01-05 | Information disclosure | private-key block split by the tail window | high | mitigate | Redact-then-tail ordering; dedicated spec with BEGIN at line 50, END at 70, tail 40 |
| T-01-06 | Information disclosure | `systemctl status` ExecStart command lines | medium | mitigate | Unit status piped through `peadm_redact` in peadm_report_failed_units |
| T-01-07 | Tampering | helper and task shell code | medium | mitigate | All expansions quoted, no eval, functions-only helper with no traps or redirects; report sizes come from Integer-typed task params |
| T-01-08 | Information disclosure | code_manager response body | medium | mitigate | Body printed only through `peadm_redact`; spec plants a token in the body |
